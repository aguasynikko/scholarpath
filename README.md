# ScholarPath

RAG-powered scholarship & financial aid navigator for Mapúa University students. Ask eligibility questions in plain language and get answers grounded in the official scholarship handbook — with page citations.

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | React 18, Vite, TypeScript, TailwindCSS |
| Backend | Node.js, Express, TypeScript |
| Search | BM25 (`wink-bm25-text-search`) — no embeddings, no vector DB |
| LLM | Llama 3.3 70B via Groq API (hosted, zero local footprint) |
| PDF parsing | `pdf-parse` |
| Validation | Zod |

## Prerequisites

- Node.js 18+
- A free [Groq API key](https://console.groq.com/keys) — no credit card required

## Setup

### 1. Place the handbook

Copy `scholarshiphandbook.pdf` into [backend/data/](backend/data/).

> The PDF must be text-based (not a scanned image). If it is scanned, run it through an OCR tool first (e.g. https://www.ilovepdf.com/ocr-pdf).

### 2. Backend

```powershell
cd backend
npm install
copy .env.example .env
# open .env and set GROQ_API_KEY to your Groq key

# Build the BM25 index from the handbook (one-time, ~5 seconds)
npm run ingest

# Start the API server with hot reload
npm run dev
```

API running at: http://localhost:8000
Health check: http://localhost:8000/api/health

### 3. Frontend

```powershell
cd frontend
npm install
npm run dev
```

App running at: http://localhost:5173

## How it works

1. **Ingest** — `npm run ingest` reads the handbook PDF, splits it into overlapping 800-character chunks, and writes them to `backend/data/chunks.json` (~5 MB). No embeddings are computed.
2. **Search** — On each chat request, BM25 lexical search retrieves the top 5 most relevant chunks from the in-memory index (~10 MB RAM).
3. **Generate** — The chunks are sent as grounded context to Llama 3.3 70B on Groq's servers. The model is instructed to answer only from the excerpts and cite page numbers.
4. **Respond** — The UI displays the answer with inline `[p.X]` citations and a collapsible source list per message.

## Re-ingesting after handbook updates

```powershell
cd backend
npm run ingest
```

Drops the old index and rebuilds from the current PDF. Restart the dev server to load the new index.

## Environment variables

Copy `backend/.env.example` to `backend/.env` and fill in:

| Variable | Description | Default |
|---|---|---|
| `GROQ_API_KEY` | Your Groq API key | _(required)_ |
| `GROQ_MODEL` | Groq model ID | `llama-3.3-70b-versatile` |
| `PORT` | Backend port | `8000` |
| `CORS_ORIGINS` | Allowed frontend origin | `http://localhost:5173` |
| `HANDBOOK_PATH` | Path to PDF | `./data/scholarshiphandbook.pdf` |
| `INDEX_PATH` | Path to chunk index | `./data/chunks.json` |

## Local footprint

- `backend/node_modules`: ~50 MB
- `frontend/node_modules`: ~200 MB
- Chunk index at runtime: ~10 MB RAM
- LLM: runs on Groq's servers — 0 MB local

## Safety notes

- **Never commit** `.env` or `backend/data/chunks.json`
- **Never modify** the handbook PDF in place — replace it and re-run `npm run ingest`
- **Never bypass retrieval** — the LLM is instructed to refuse eligibility questions it cannot ground in the handbook
- Student profile data (GWA, income, program) is sent to Groq's API on every chat call — inform pilot users before deploying beyond dev
